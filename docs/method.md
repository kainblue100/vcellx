本文补足 README 里没展开的实现决策，重点是那些**做错了会让结论失效**的地方。

## 1. 为什么是集合，不是单细胞

单细胞 RNA 测序是破坏性的。要预测「扰动后的细胞」，最自然的写法是

```
X_p = T_p(X_0) + ε
```

但 `X_0` 永远观测不到 —— 测量发生时细胞已经被裂解。任何逐细胞配对都是**强行指定**的，
不携带信息。

于是把视角从细胞换到分布：

```
𝒟_p ≈ T_p(𝒟_basal) + H(𝒟_basal) + ε
```

`𝒟_basal` 是可观测的（对照细胞群）。模型因此学的是「一整组细胞怎么变形」，
而不是「这个细胞变成那个细胞」。

**实现**：每个训练样本是一个 `(S, G)` 的对照集合配一个 `(S, G)` 的观测扰动集合，
`S = 64`。损失在两个集合的经验分布之间计算。

### 1.1 MMD 损失

用能量距离核 `k(a,b) = −‖a−b‖` 的平方 MMD：

```
MMD² = 2·E‖x−y‖ − E‖x−x′‖ − E‖y−y′‖
```

三项分别是**跨集相似度**、**预测集内部相似度**、**观测集内部相似度**。
当两个集合完全重合时三项相等，MMD² = 0。

实现里用 `torch.cdist` 一次得到三个成对距离矩阵，内部两项要**排除对角线**
（否则 `E‖x−x′‖` 被自距离 0 拉低，损失会系统性偏小 —— 这是个容易写错的地方）。

### 1.2 集合怎么配

按 `(target_gene, batch)` 分组，组内切不重叠的 `S` 个细胞。
对照集合从**同一 batch** 随机抽 `S` 个未扰动细胞。

只在 batch 上匹配，因为训练文件里只有这一个混杂协变量。
若不匹配 batch，模型会去学批次差异而不是扰动效应。

## 2. 三臂设计

```python
z_p = emb[p] + epi_pathway(p)      # emb 三臂共享

epi_pathway(p):
  graph    = W @ (A_norm @ E)[p]      A_norm 每行和为 1
  shuffle  = W @ (A_shuf @ E)[p]      同度，不同拓扑
  direct   = W @ E[p]                 无图
```

`E ∈ R^{G×k}` 是逐基因表观特征，`W ∈ R^{k×d}` 是线性投影，`d = 256`。

### 2.1 为什么必须有 shuffle 臂

`graph` 臂看到的是**靶基因邻居的表观特征聚合**，`direct` 臂只看到靶基因自己的。
两者输入的信息量不同。如果只比较这两个，`graph` 赢了也无法区分：

- 图拓扑携带了调控信息（我们想证明的）
- 图传播只是让模型看到了更多特征（平庸解释）

`shuffle` 臂保持每个节点的**度分布完全不变**，只随机改接边。
因此它看到的特征数量和 `graph` 一样多，唯一变化是**谁连谁**。

判读规则：

| 观察 | 结论 |
|---|---|
| graph > shuffle > direct | 拓扑有用，且信息量也有用 |
| graph ≈ shuffle > direct | 只有信息量有用，**拓扑没用** |
| graph > shuffle ≈ direct | 拓扑有用 |
| 三者相近 | 表观先验在这个任务上没用 |

### 2.2 度匹配打乱怎么实现

受约束的换边（constrained edge transposition）：

1. 随机取两条边 `(u1→t1)`、`(u2→t2)`
2. 若 `t1 ≠ t2` 且 `u1 ≠ u2`，且交换后不产生重复边
3. 则交换目标：`(u1→t2)`、`(u2→t1)`

每个节点的**出度精确不变**，但邻接关系被逐步打乱。默认做 `20 × 边数` 次换边尝试。

## 3. GRN 构造

**第一版方案已实测否决**，记录在这里因为它是个有用的负面结果。

### 3.1 被否决的方案：juicer 环调用

最初用 K562 的 ENCODE Hi-C **环调用**（juicer_tools bedpe，4 个文件共 52,276 个环）：
若一个环的两个锚点分别覆盖两个基因的启动子窗口，则加边。

实测（2000 基因 HVG 面板）：

| promoter 窗口 | 边数 | 孤立基因 | 中位度数 | 最大度数 |
|---|---:|---:|---:|---:|
| ±1 kb | 15 | 1972 / 2000 | 0 | 2 |
| ±5 kb | 27 | 1949 / 2000 | 0 | 3 |
| ±25 kb | 119 | 1797 / 2000 | 0 | 3 |
| ±100 kb | 890 | 1080 / 2000 | 0 | 9 |

**即使把启动子窗口放宽到 ±100 kb，中位度数仍是 0。** 原因是结构性的：
环调用是**位点对位点**的，全基因组只有 5 万个，而面板只取 2000 个基因，
两个锚点同时撞上面板基因的概率极低。这不是参数没调好，是数据源不合适。

顺带修了一个静默 bug：`read_loops` 用 `line.startswith('#')` 跳过表头，
而 juicer 的表头以 `#chr1` 开头，导致 `header` 永远为 `None`，
**FDR 阈值从来没生效过**（0.05 / 0.2 / 1.0 三档结果完全相同就是这个原因）。

### 3.2 采用的方案：bin 级接触矩阵

改用 4DN 的 **HFFc6 Hi-C 多分辨率矩阵**（`4DNFIB59T7NN.mcool`，22.8 GB，
13 档分辨率）。`.mcool` 就是 HDF5，直接用 h5py 读取，不需要 cooler：

```
resolutions/100000/bins      chrom, start, end       30,894 bins
resolutions/100000/pixels    bin1_id, bin2_id, count  346,823,799 对
resolutions/100000/indexes   bin1_offset              ← 只读需要的 bin
```

做法：把每个基因的 TSS 映射到 bin，用 `bin1_offset` **只读取含有面板基因的那些
bin 的像素**（否则要读 3.5 亿对），两个 bin 都含面板基因时在其中的基因之间加边，
权重用接触计数，保留计数在 90 分位以上的强接触，每节点保留 top-10。

实测结果：

```
边数        12,015
孤立基因    50 / 2000
中位度数    11
平均度数    12.0
最大度数    28
分辨率      100 kb
```

**必须说明的解释边界**：100 kb 的一个 bin 里通常有好几个基因，
所以一条边的含义是「这两个基因处在互相接触的 100 kb 区间内」，
**不是**「这两个启动子之间有环」。这是分辨率带来的粗糙化，
写进图摘要里随结果一起报告：

```json
"note": "bins hold several genes at this resolution, so an edge means
         'contacting bins', not a promoter-promoter loop"
```

### 3.3 度匹配打乱

受约束换边：随机取两条边，交换两个节点的目标，若不产生重复边才接受。
每个节点的出度**精确不变**，只有连接关系变化。实测执行 480,600 次换边。

### 3.4 表观特征

每个基因 8 维（ATAC、CTCF、SP1、USF1 各两维：log1p 信号和峰数），
promoter 窗口 TSS ± 1 kb，来自 GENCODE v44：

| 特征 | 覆盖基因比例 |
|---|---:|
| ATAC | 77.6% |
| CTCF | 25.0% |
| SP1 | 23.4% |
| USF1 | 22.4% |

1957/2000 个面板基因找到 TSS，1563 个在启动子内至少有一个峰。

### 3.5 已知的偏离

- 表达数据是 Arc VCC 训练集（README 未声明细胞系），表观数据是
  **K562（ATAC/TF）与 HFFc6（Hi-C）**，因此这是**跨背景的调控先验**
- 只用单跳传播，没有多跳也没有注意力加权
- WGBS 甲基化特征已下载但尚未接入

## 4. 预训练

```
输入   4096 基因面板 log1p-CP10k
掩码   每细胞随机遮 30% 基因
编码   剩余 70% → 256 维
解码   只重建被遮住的位置
```

**只对被遮住的位置算损失**是这一步的核心。若对全部位置算重建损失，
恒等映射就能把损失降到很低，编码器学不到任何东西。

面板选择：
1. 取 Arc 与 Tabula 的基因符号交集
2. 在 Tabula 的 12 万细胞子样本上算方差
3. 取方差最高的 4,096 个
4. 记录顺序，后续所有环节共用

**不碰 Arc 扰动细胞**，避免特征选择泄漏。

### 4.1 CPU 上的现实约束

`4096 → hidden` 这一层主导 FLOPs。实测（共享服务器，约 4 核可用）：

| 配置 | 每 epoch |
|---|---|
| hidden 1024, 400k 细胞 | ~20 min |
| hidden 512, 150k 细胞 | ~17 min |

模型参数量 3.41 M。共享环境下 16 线程只拿到约 4 核，这是主要的瓶颈。

## 5. 切分与防泄漏

| 环节 | 做法 |
|---|---|
| 靶基因切分 | **靶基因不相交**：98 / 22 / 30，同靶不同时出现在训练与测试 |
| HVG 选择 | 只用对照细胞 |
| 归一化统计 | 只用对照细胞 |
| 预训练面板 | 只用外部数据方差 |
| 表观建图 | 不看表达数据 |
| 对照匹配 | 同 batch，避免学批次 |

## 6. 评测

`cell-eval2 0.22.0`，`vcc2026` preset。三类读出口：

1. **表达量**：扰动后表达变化的 Pearson
2. **差异表达**：DE 基因 AUPRC、倍数变化 Spearman、top-k 重合
3. **效应量**：扰动强度排序的 Spearman

基线：`control-only`、`mean-response`、`direct`、`shuffle`、`graph`。
STATE 的数字只以**论文公布值**形式出现，且明确标注不是本仓库复现 ——
数据集、切分、上下文都不同，并排比较本身有误导性。
